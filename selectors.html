Editable Selectors

Editable Selectors tell Klar which parts of your page can be edited — and how. It works like CSS: you target elements with selectors, then attach behaviors with :directives. Where CSS says "make .hero blue," Klar says "make .hero editable."

"It's CSS, but for editability"

Bare selector :exclude :list :attr :style :readonly :snapshot :blocks :htmlBlocks

1

Bare selector

.hero

A selector with no suffix simply marks an element as editable. The element itself and its default-editable descendants — headings (h1–h6), paragraphs, links, buttons and list items — become click-to-edit. This is the everyday case: point at a region and its text turns into content a user can change directly on the page.

Once your editableSelectors list is non-empty, editability is opt-in — only listed selectors and their default-editable children can be edited.
2

Exclude

.hero:Exclude(img, a)

Keeps the container editable but carves specific descendants out of it. Everything inside stays click-to-edit except the elements matched by the selectors in the parentheses.

  • The heading and paragraphs in the hero stay editable.
  • The img and a are frozen — a user can't accidentally retype the link text or delete the image.
  • Use it to protect structural or decorative pieces that live inside an otherwise-editable block.
3

List

.features:list

Marks a repeatable container. Its direct children become items the editor can duplicate, reorder, and remove — perfect for feature grids, card rows, stats and steps.

  • Each direct child is treated as one repeatable item.
  • Users add more by duplicating, drag to reorder, click to remove.
  • Alias: .features[] means the same thing.
4

Attribute

img.logo:attr(alt)

Makes an element's attribute editable rather than its text. The editor exposes the named attribute in the panel so a user can change it without touching inline content.

  • img.logo:attr(alt) — edit the logo's alt text for accessibility.
  • Add a value picker with labelled choices:
.badge:attr(data-status[Active=active, Inactive=inactive]) The editor shows friendly labels (Active, Inactive) and writes the underlying values (active, inactive) to the attribute.
5

Style

.hero__bg:style(background-image)

Lets a user edit the element's CSS background-image through Klar's media picker. Instead of editing text, they swap the background of a section by choosing an image — ideal for hero bands and cover panels where the picture is applied as a background rather than an <img>.

6

Read-only

footer:readonly

The element is selectable and listed in the editor panel, but not inline-editable. A user can see it in the structure and click it, yet can't change its content directly — useful for legal footers, shared boilerplate, or anything that shouldn't be casually rewritten.

7

Snapshot

.cached-price:snapshot

Freezes the element's content at save time. Whatever the element contains when the page is saved is captured and locked in — later dynamic changes won't alter it. It implies read-only, so the frozen content can't be edited inline either. Handy for caching a computed value or a timestamp exactly as it stood at publish.

8

Blocks

.content:blocks

Turns the element into a drag-and-drop block container. A user can add, reorder and remove content blocks inside it — headings, paragraphs, images and more — arranging a page section by dragging pieces into place rather than editing a fixed layout.

9

htmlBlocks

.layout:htmlBlocks

Like :blocks, and additionally auto-discovers nested container descendants as block zones. One directive on an outer wrapper makes not just it, but every nested container inside it, into its own drag-and-drop region — ideal for multi-zone layouts where several areas should each accept blocks.

Directives shape the editing experience.

Combine a bare selector with :exclude, :attr, :list and the rest to decide exactly what your editors can touch — and what stays safe.
